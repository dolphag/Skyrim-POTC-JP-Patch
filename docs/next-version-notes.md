1. **テスト版のファイル名**: `POTC_ja_<版>_test<N>.zip`、メモ1行目にも版を入れる(`make_zip.py test --version`、1.2.0-1 の作業中に実装済み。CLAUDE.md・skill に反映)。通し番号 N は版ごとに 1 から。
2. **Nexus の Description は版ごとに更新しない**。版で変わる情報(対応する Paths の版、POTC Effects・FWM 用パッチの版、権限の確認日)を Description から外し、ファイルの説明欄と Changelog に移した(`release/NEXUS_DESCRIPTION.bbcode.txt`。次にページを編集するときに反映する。この版の Nexus ページは旧文面のまま)。権限の確認日は zip 内 README に残す(CLAUDE.md の規定)。
   - 毎回更新するもの: Changelog、ファイルの説明欄(対応版・前提の版)。zip 内 README(版・SHA・更新履歴)。
   - 限界: 前提の版(POTC Effects など)は Nexus の「Requirements」と原作のページを正とする。

## 相談中(未決): 原作 Description の日本語版
ユーザーの案: 原作 Description を日本語に訳して、(a) 翻訳精度の向上のために解析対象にする、(b) 日本語パッチの Description に載せる(画像は原作のものを使う)、(c) MOD に日本語 HTML を入れる案も。

### 事実(確認済み)
- 原作の zip に、英語の文書が同梱されている: `README.md`(約 30 KB、1.2 の説明・設定・ツリー・特性)、`docs/SKALD.md`(約 39 KB)、`docs/PARTY-BALANCE.md`、`docs/RELEASE-NOTES.md`。Nexus の Description と同じ内容かどうかは**未確認**(Nexus のページ本文は未取得)。
- 権限(2026-11-01 にユーザーが貼付で確認): 他サイトへの転載・改変・素材の利用は、作者のクレジット表記で可。Description の翻訳の掲載も、権限の範囲内と考えられる(未確認なのは、原作者が Description 本文の翻訳をどう受け取るか)。
- 1.2.0 の作業で、用語の取り違えが実際にあった(スカルド解放の「skill points」がパークポイントと同じか、スタックの意味など)。機能を理解しないまま訳した結果。

### 論点
- (a) 解析材料としては、zip 同梱の `README.md` / `docs/` を読めば足りる可能性が高い(版に対応した一次情報)。**まずこれを使う**ほうが先で、Description を訳す必要はない。
- (b) の維持コストは、上の 2(Description を版ごとに更新しない)と衝突する。原作の Description は版ごとに変わる。訳を載せると、更新のたびに追随するか、古いまま残るかになる。載せるなら、パッチの Description ではなく、**独立した文書**(別ページ、または記事)にして、パッチの版と切り離す。
- (c) HTML の同梱は、開く手間のわりに読まれにくい。zip 内の `README_Japanese.txt` に入れる案も、README が長くなる。
- 需要は仮説(ブラウザの翻訳で足りる、という反論をユーザー自身が挙げている)。ダウンロード数・コメントなど、根拠はまだ無い。

### 提案(順序)
1. 次の版から、zip 同梱の `README.md` / `docs/` を**翻訳前の読み物として使う**(公開しない。調査メモは自分の言葉で `docs/` に書く。原文の写しは GitHub に置かない)。用語集 `GLOSSARY.md` の根拠にする。
2. 需要が見えたら(コメント・要望)、独立した日本語ガイドを検討する。載せる先は、パッチの Description ではない。
3. 原作者に確認するなら、ユーザーが行う(CLAUDE.md の規定。原作者への連絡は許可制)。
